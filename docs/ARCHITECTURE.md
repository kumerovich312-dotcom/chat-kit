# Как устроен набор

Набор — одна основа переписки с клиентами для Атласа, TishCRM и студии. Он ничего не хранит сам: клиенты, сообщения,
файлы, сотрудники и права — в базе проекта. Набор даёт окно переписки, правила и подключения каналов, а проект —
один файл-«переходник» к своей базе.

```
канал (Nextbot / шлюз WhatsApp / студия)
   │ уведомление (вебхук)
   ▼
«розетка» — подключение канала (src/nextbot, src/wa-gateway, src/studio): разобрать уведомление в события
   ▼
приём (src/server/ingest.ts): клиент → сообщение без повторов → «ждёт ответа» → сообщить вкладкам; файлы — после ответа каналу
   ▼
«переходник» проекта (ChatStore): его SQL к его базе, его правила (сделка, дубли, права)
   ▼
база проекта → страница проекта → окно переписки набора (src/ui) → ответ менеджера → подключение → канал
```

## Части и как их подключать

| Путь в пакете | Что внутри | Где работает |
|---|---|---|
| `@muras/chat-kit` | ядро: модель сообщения с автором, порядок и повторы, «ждут ответа» (TS и SQL), телефоны, файлы, разметка под канал, время по поясу, ссылки wa.me / t.me, форма поля ввода | сервер и браузер, без зависимостей |
| `@muras/chat-kit/server` | «розетка» (ChannelAdapter), «переходник» (ChatStore), приём `ingest`, скачивание файлов с проверками, тип файла по содержимому, подписанные ссылки на файлы, переходник «в памяти» для проверок | только сервер (node:crypto) |
| `@muras/chat-kit/nextbot` | подключение Nextbot, перенесённое из Атласа: разбор событий, «Полный диалог», время и автор, файлы, отправка, маршрут приёма | только сервер |
| `@muras/chat-kit/wa-gateway` | подключение к шлюзу WhatsApp TishCRM: очередь исходящих через проект, событие «пациент написал», управление по HTTP, авторы TishCRM | только сервер |
| `@muras/chat-kit/studio` | заготовка подключения студии по разделу 10.8 плана: подпись вебхуков, события, команды | только сервер |
| `@muras/chat-kit/ui` | окно переписки (React 19) | страница проекта |
| `@muras/chat-kit/styles.css` | стили окна на переменных `--ck-*` | один раз в корневом layout |

## Модель сообщения (`src/core/model.ts`)

- **Автор** — как в плане студии (10.2, D-041): `client`, `bot`, `operator_crm` (менеджер из CRM), `operator_phone`
  (менеджер с телефона), `operator_admin` (администратор студии; у Nextbot — «менеджер в Nextbot»), `system`.
- **Вид записи**: `message` (пузырь), `note` (заметка команды, клиент не видит), `system` (служебная строка), `call` (звонок).
- **Время** `at` — ISO с миллисекундами; `seq` — номер по порядку, если канал его даёт (студия): порядок по нему надёжнее.
- **Доставка** `delivery`: pending → sent → delivered → read, или failed с причиной.
- **Повтор** — `externalId` (номер у канала): второй раз не записывается.
- `handoff` — бот позвал человека; `shadow` — черновик бота, клиенту не ушёл.

## Правила ядра

- **«Ждут ответа»** (`waitSince`): клиент написал, а ему не ответили — ни бот, ни менеджер, ни внесённая копия.
  Заметки, служебные строки, звонки, недоставленное и черновики — не ответ; «Ответ не нужен» снимает ожидание до
  следующего сообщения клиента; «передаю менеджеру» от бота — не ответ. Для списков из тысяч клиентов тот же расчёт
  делает `waitSinceSql` — подзапрос для Postgres; совпадение проверено на 300 случайных диалогах (PGlite).
- **Порядок**: `seq`, иначе время до миллисекунды, при равном — номер записи. `placeAfter` — время для «неточного»
  канала: не раньше предыдущего известного сообщения и не позже «сейчас».
- **Телефоны**: `normalizePhone` (+код по стране компании), `samePhone` — целиком, если оба номера с кодом страны, иначе
  по 9 последним цифрам (у +7 Казахстана и России 9 цифр совпадают у разных людей), `phoneTail` — ключ поиска.
- **Разметка**: `formatForChannel` — ответ ИИ (Markdown) под канал: WhatsApp `*жирный*`, Telegram HTML, иначе текст.
  В окне — `parseRich`: дерево без вставки HTML.
- **Время**: всё по поясу компании (`timeZone: "Asia/Bishkek"`), время сообщения — до секунды.

## «Розетка» (`src/server/channel.ts`)

Подключение умеет: `receive` (разобрать уведомление в события), `send` (текст или файл), `control` (пауза /
возобновление / «не отвечать»), `download` (скачать файл), по желанию `apply` (свои «особые» события — у Nextbot так
разбирается «Полный диалог») и `respond` (свой ответ каналу). `caps` — что канал умеет: окно показывает только
доступные кнопки. Смена подключения — настройка проекта: `createNextbotAdapter(...)` → `createStudioAdapter(...)`.

События: `message`, `status`, `notice` (служебная строка один раз), `state` (кто ведёт диалог), `handoff`, `lead`,
`function` (бот просит данные у CRM — «Найти вакансии»), `refresh` (сообщение уже в базе — только обновить экраны),
`ping`, `custom`.

## «Переходник» (`src/server/store.ts`)

Проект пишет пять вещей: `findOrCreateContact`, `saveMessage` (без повторов по `externalId`), `saveFile`,
`markWaiting` (может ничего не делать, если «ждут ответа» считается запросом), `notify` (сообщить открытым вкладкам).
По желанию — для «неточных» каналов (Nextbot): `messageExists`, `findMessages`, `updateMessage`, `state` («ключ →
значение»). Разделение компаний (`org_id`, RLS) — внутри переходника: проект создаёт его уже для своей компании.
Образец — `createMemoryStore` (переходник «в памяти»).

## Окно переписки (`src/ui`)

- Лента (`ChatThread`), список (`DialogList`), шапка (`DialogHeader`), окно целиком (`ChatWindow`) — без состояния:
  годятся и для серверной страницы (Атлас), и для браузера. Места для проекта — функции, которые возвращают готовую
  разметку (`renderActions`, `renderAttachmentExtra`, `renderSystem`, `viewerPanel`), и действия-формы (server actions).
- Поле ввода (`Composer`), поиск (`ChatFind`), голосовое (`VoicePlayer`), просмотр фото (`FileViewer`), уведомления
  (`WaitAlerts`) — клиентские части. Поле отправляет одну форму (`readComposerForm` читает её на сервере).
- Места для студии (решения пользователя 27.09.2026): кнопки бота в шапке (`BotControls`), «второй пилот» (`copilot`),
  оценка ответов бота и «как надо было» (`teach.rate` — владельцу, менеджерам по доступу), «Сделать примером для бота»
  (`teach.example`), «Что бот знает о клиенте» (`memory`).
- Картинки и голосовые — по прямым ссылкам сайта проекта, без `blob:`-адресов (CSP студии). Перемотка голосового
  требует, чтобы адрес файла отдавал его кусками (заголовок Range) — у Атласа так и есть.

## Стили

Свои, без Tailwind, классы `ck-…`, переменные `--ck-*` (список — начало `src/ui/styles.css`). Значения по умолчанию —
палитра Атласа; проект задаёт свои в `:root`. Темы TishCRM и студии для примера — `demo/demo.css`.

## Сборка и выпуск

Код пишется на TypeScript с расширениями `.js` в путях импорта (так собранный код открывается и Node, и сборщиками
Next.js). `npm run build` — `tsc` в `dist/` + стили; в выпуск (`.tgz`) идут только `dist`, README и CHANGELOG.
Строгость TypeScript — как у студии (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`).
