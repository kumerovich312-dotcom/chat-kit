# Как устроен набор

chat-kit — нейтральная основа переписки с клиентами для любого проекта. Он ничего не хранит сам: клиенты, сообщения,
файлы, сотрудники и права — в базе проекта. Набор даёт окно переписки, правила и подключения каналов, а проект —
паспорт (слова отрасли, что включено, свои карточки и кнопки) и один файл-«переходник» к своей базе.

```
канал (Telegram / WhatsApp / Instagram / почта / звонки / чат на сайте / Nextbot / ИИ-студия)
   │ уведомление (вебхук)
   ▼
«розетка» — подключение канала (src/channels/<канал>): проверить подпись, разобрать уведомление в события
   ▼
приём (src/server/ingest.ts): клиент → сообщение без повторов → «ждёт ответа» → сообщить вкладкам; файлы — после ответа каналу
   ▼
«переходник» проекта (ChatStore): его SQL к его базе, его правила (заявка, дубли, права, разделение компаний)
   ▼
база проекта → страница проекта → окно переписки набора (src/ui) + паспорт проекта → ответ сотрудника → подключение → канал
```

## Части и как их подключать

| Путь в пакете | Что внутри | Где работает |
|---|---|---|
| `@muras/chat-kit` | ядро: модель сообщения с автором, порядок и повторы, «ждут ответа» (TS и SQL), телефоны, файлы, разметка под канал, время по поясу, ссылки wa.me / t.me, форма поля ввода, **паспорт проекта**, **команда** (статусы, «отложить до», раздача, метки, присутствие), **статистика ответов** (TS и SQL) | сервер и браузер, без зависимостей |
| `@muras/chat-kit/server` | «розетка» (ChannelAdapter), «переходник» (ChatStore), приём `ingest`, скачивание файлов с проверками, тип файла по содержимому, подписанные ссылки, присутствие коллег (`createPresenceHub`), голосовое WebM → Ogg, переходник «в памяти» | только сервер |
| `@muras/chat-kit/telegram`, `/instagram`, `/green-api`, `/email`, `/calls`, `/site`, `/nextbot`, `/studio` | подключения каналов (описания — `docs/channels`) | только сервер |
| `@muras/chat-kit/widget` | чат на сайте — один файл для `<script type="module">`, без зависимостей, в Shadow DOM | сайт компании |
| `@muras/chat-kit/ai` | «розетка ИИ»: расшифровка, «Кратко», «Улучшить текст», настроение и срочность; Claude, сервис расшифровки с API как у OpenAI, поддельный ИИ | сервер |

## Паспорт проекта (`src/core/profile.ts`)

Всё, чем проект отличается, — в одном объекте `defineProfile({...})`: слова отрасли в нужных падежах (клиент /
пациент / кандидат…; `NOUNS`), любые надписи окна (`texts`), что включено (`features`), метки (`tags`), свои карточки
в ленте (`cards`: запись, счёт, вакансия — заголовок, значок, цвет, поля, статус), свои кнопки меню «+» (`actions`:
вставить текст, открыть страницу проекта, маленькая форма → действие проекта), цвета (`theme` → `profileCss`).
Паспорт — простые данные: его можно хранить в базе и отдавать браузерным частям окна.

## Модель сообщения (`src/core/model.ts`)

- **Автор**: `client`, `bot`, `operator_crm` (менеджер из CRM), `operator_phone` (менеджер с телефона), `operator_admin`
  (администратор; у Nextbot — «менеджер в Nextbot»), `system`.
- **Вид записи**: `message` (пузырь), `note` (заметка команды, клиент не видит), `system` (служебная строка), `call` (звонок).
- **Время** `at` — ISO с миллисекундами; `seq` — номер по порядку, если канал его даёт: порядок по нему надёжнее.
- **Доставка** `delivery`: pending → sent → delivered → read, или failed с причиной.
- **Повтор** — `externalId` (номер у канала): второй раз не записывается.
- **Цитата** `replyTo` (ответ на сообщение), **карточка проекта** `card`, **расшифровка** у вложения `transcript`,
  `handoff` — бот позвал человека, `shadow` — черновик бота.
- Диалог (`src/core/conversation.ts`): статус (открыт / отложен / закрыт), метки, ответственный, оценка ИИ
  (настроение и срочность), присутствие коллег, состояние бота.

## Правила ядра

- **«Ждут ответа»** (`waitSince` + `waitSinceSql`): клиент написал или не дозвонился, а ему не ответили — ни бот, ни
  менеджер, ни внесённая копия, ни состоявшийся разговор по телефону. Заметки, служебные строки, недоставленное и
  черновики — не ответ; «Ответ не нужен» снимает ожидание до следующего сообщения клиента; «передаю менеджеру» от бота —
  не ответ. SQL-двойник проверен на Postgres (PGlite) на случайных диалогах.
- **Статус** (`effectiveStatus` + SQL): отложенный сам открывается, когда пришло время или клиент написал; закрытый —
  когда клиент написал. **Статистика** (`episodesOf` / `responseEpisodesSql` + `responseStats`): скорость первого
  ответа, доля в срок, люди и бот, по менеджерам и каналам — подробно в [TEAM.md](TEAM.md).
- **Порядок**: `seq`, иначе время до миллисекунды, при равном — номер записи.
- **Телефоны**: `normalizePhone` (+код по стране компании), `samePhone` — целиком, если оба номера с кодом страны.
- **Разметка**: `formatForChannel` — ответ ИИ под канал (WhatsApp `*жирный*`, Telegram HTML, иначе текст); в окне —
  `parseRich` (дерево без вставки HTML), одним проходом: особый текст клиента не «подвешивает» страницу.
- **Время**: всё по поясу компании, время сообщения — до секунды.

## «Розетка» (`src/server/channel.ts`)

Подключение умеет: `receive` (проверить подпись и разобрать уведомление в события), `send` (текст, файл, цитата),
`control` (пауза / возобновление / «не отвечать»), `download` (скачать файл), по желанию `apply` (свои «особые»
события) и `respond` (свой ответ каналу). `caps` — что канал умеет: окно показывает только доступные кнопки.
События: `message`, `status`, `notice`, `state`, `handoff`, `lead`, `function`, `call`, `refresh`, `ping`, `custom`.

## «Переходник» (`src/server/store.ts`)

Проект пишет пять вещей: `findOrCreateContact`, `saveMessage` (без повторов по `externalId`), `saveFile`,
`markWaiting` (может ничего не делать, если «ждут ответа» считается запросом), `notify`. По желанию — `messageExists`,
`findMessages`, `updateMessage`, `state` («ключ → значение»). Разделение компаний — внутри переходника.

## Окно переписки (`src/ui`)

- Лента (`ChatThread`), список (`DialogList`), шапка (`DialogHeader`), окно целиком (`ChatWindow`) — без состояния:
  годятся и для серверной страницы, и для браузера. Места для проекта — функции, которые возвращают готовую разметку,
  и действия-формы (server actions).
- Клиентские части: поле ввода (`Composer`: вкладки, шаблоны, файлы, цитата, запись голосового, «Улучшить текст»,
  меню «+»), поиск (`ChatFind`), фильтр (`ThreadFilter`), «Кратко» (`SummaryBar`), все файлы клиента (`ClientGallery`),
  полоса статуса и меток (`DialogStrip`), голосовое (`VoicePlayer`), просмотр фото (`FileViewer`), уведомления
  (`WaitAlerts`), места для ИИ-бота (`BotControls`, «второй пилот», оценка ответов, примеры, память бота).
- Решения пользователя по виду (27.09.2026) — `docs/ROADMAP.md`.
- Картинки и голосовые — по прямым ссылкам сайта проекта, без `blob:`-адресов. Перемотка голосового требует, чтобы адрес
  файла отдавал его кусками (Range).

## Стили

Свои, без Tailwind, классы `ck-…`, переменные `--ck-*` (список — начало `src/ui/styles.css`). Значения по умолчанию —
спокойная синяя палитра; тёмная тема — `data-ck-theme="dark"` / `"auto"`; проект задаёт свои цвета в `:root` или из
паспорта (`profileCss`).

## Сборка и выпуск

Код пишется на TypeScript с расширениями `.js` в путях импорта (так собранный код открывается и Node, и сборщиками
Next.js). `npm run build` — `tsc` в `dist/` + стили; в выпуск (`.tgz`) идут `dist`, `docs`, README и CHANGELOG.
Строгость TypeScript — `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`. Зависимостей нет (React —
только для окна).
