# Студия и набор

Студия (Muras AI Studio, проект aibots) — третий пользователь набора и будущий главный канал вместо Nextbot.

## Когда

- API студии для CRM появится на **этапе 5** её плана (раздел 10.8). До этого в наборе — заготовка подключения
  `@muras/chat-kit/studio` по плану: подпись вебхуков, события, команды.
- В записях самой студии (DECISIONS.md, «Расхождения», п. 9 в ветке её чата) переход на набор отмечен как «требует
  подтверждения пользователя» — это подтверждение даётся в чате студии.

## Что уже совпадает с планом студии

- Авторы сообщения — те же значения, что в плане (D-041): `client / bot / operator_crm / operator_phone /
  operator_admin / system`.
- Порядок — `seq`, повтор — номер сообщения у канала, время — до миллисекунды (10.4).
- Команды «пауза / вернуть боту / не отвечать этому клиенту» (10.5) — `BotCommand`, кнопки `BotControls`.
- Подпись вебхуков `X-Signature: t=…,v1=HMAC-SHA256(t.тело)`, `Idempotency-Key` у команд, ошибка 409 при повторе ключа
  с другим телом (10.8) — в заготовке.
- Разметка ответа под канал (`markdownMode` студии: telegram / plain) — `formatForChannel` ядра.

## Что сверить, когда выйдет API

Заготовка принимает оба вида, но окончательное решает студия:
- типы событий с суффиксом `.v1` или без;
- поля `snake_case` или `camelCase`;
- значения режимов диалога (`control_mode`, `handoff_status` — в плане и D-010 расходятся);
- коды причин оценки ответа бота: в студии пока только слова, в наборе — предварительные коды (`FEEDBACK_REASONS`).

## Места для студии в окне (решения пользователя 27.09.2026)

| Место | Что показывает | Что должна дать студия |
|---|---|---|
| Кнопки бота в шапке + пометка | «бот ведёт диалог», «бот на паузе до 18:30», «бот не отвечает» | `conversation.state_changed`, команды `/pause`, `/resume`, `/contacts/{id}/mute` |
| «Второй пилот» | ответ, который бот предлагает на каждое сообщение клиента, когда диалог ведёт человек | черновик ответа (теневой режим: `message.created` с `is_shadow` или отдельная команда «предложи ответ») |
| Оценка ответа бота | «Хорошо / Как надо было / Опасно», причина и правильный ответ | приём `feedback` (4.4, 10.7) |
| «Сделать примером для бота» | у ответа менеджера на вопрос клиента | приём кандидата в примеры (`proposal` / `example` с `source = manager_reply`) |
| Что бот знает о клиенте | профессия, страна, сроки, бюджет — править и удалять | `contact.memory_updated`, `PATCH /contacts/{id}/memory` |

Оценка и примеры — у владельца сразу, у менеджеров — когда владелец даст доступ: проект передаёт `teach` в окно
только тем, кому можно.

## Окно в самой студии

Студия может показывать диалоги тем же окном (Next.js 16, свои стили без Tailwind — набор с ними работает): тема —
переменными `--ck-*` из её `globals.css` (пример — тема «Студия» на демо-странице). Ограничения студии, которые набор
уже соблюдает: строгий TypeScript (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`), без `blob:`-адресов
(CSP), текст бота не вставляется как HTML, в коде нет строк, на которые ругается её поиск секретов.
