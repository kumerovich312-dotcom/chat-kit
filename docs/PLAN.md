## Что входит в набор

1. **Окно переписки** (React): список диалогов и «Ждут ответа»; лента как в WhatsApp с автором каждого сообщения
   (клиент, бот «ИИ-агент», менеджер из CRM, менеджер с телефона, служебное), время до секунды; поле ввода (Enter —
   отправить, вкладки «Клиенту / В историю / Заметка / Письмо» по желанию проекта, шаблоны, файлы, сообщение сразу
   с часиками); голосовые с волной; просмотр фото с лупой и поворотом и местом для кнопок проекта; вложения PDF / DOC / XLS;
   поиск внутри переписки; уведомления со звуком (один звонок на одно ожидание). Места для идей студии: действия
   у сообщения, черновик ответа от бота, кнопки «пауза бота / вернуть боту / не отвечать этому клиенту».
2. **Ядро** (TypeScript без базы): сообщение с автором; порядок и защита от повторов; правило «ждут ответа»; телефоны;
   ссылки на файлы; разметка ответа под канал (WhatsApp `*жирный*`, Telegram HTML, иначе текст).
3. **«Розетка» каналов** — общий вид подключения: разобрать входящее уведомление, отправить текст или файл, пауза /
   возобновление / «не отвечать», скачать файл. Подключения: Nextbot (из Атласа), шлюз WhatsApp TishCRM, студия (заготовка).
4. **«Переходник»** — описание того, что проект должен уметь со своей базой: найти или создать клиента по телефону или
   внешнему номеру, записать сообщение без повторов, сохранить файл, отметить «ждёт ответа», сообщить открытым вкладкам.
5. **Стили** на CSS-переменных — каждый проект задаёт свои цвета, шрифт, скругления.
6. **Проверки** на обезличенных примерах и **демо-страница** (порт 30030).

## Что остаётся в каждом проекте

Клиенты / пациенты, сообщения в своей базе, сотрудники и права, разделение компаний (`org_id` в каждом запросе),
сделки / записи / документы («Куда положить»), свои шаблоны ответов, ключи и настройки каналов, свои кнопки в местах
расширений, адреса приёма вебхуков и выдачи файлов, живое обновление экранов (SSE или опрос).

## Как проект подключает набор

1. Кладёт копию набора к себе (способ — ниже).
2. Пишет «переходник» к своей базе — один файл.
3. Задаёт свои цвета и шрифт — несколько строк CSS.
4. Ставит окно переписки на свою страницу, подключение канала — на свой адрес приёма, прогоняет свои проверки.

## Способ доставки — варианты

Главное ограничение: серверы Атласа и TishCRM собирают приложение из своего git без доступа к другим репозиториям GitHub.
В обоих Dockerfile `npm ci` идёт по package.json раньше, чем копируется остальной код; у TishCRM — старый сборщик без
секретов.

| | А. Копия в `vendor/chat-kit` скриптом, с номером версии | Б. Открытый репозиторий набора | В. Закрытый пакет с ключом на серверах |
|---|---|---|---|
| Сборка на сервере | ничего не меняется: `COPY . .` уже копирует папку | `npm ci` качает набор с GitHub при каждой сборке | нужен ключ в сборке; у TishCRM старый сборщик — ключ попал бы в образ |
| Ключи | не нужны | не нужны | ключ на каждом сервере |
| Когда проект обновляется | когда сам решит, в своём чате, по своим проверкам | по номеру версии в package.json | по номеру версии |
| Правки | только в chat-kit; копия сверяется списком отпечатков файлов | только в chat-kit | только в chat-kit |
| Что менять в проекте | псевдоним `@chat-kit/*` в tsconfig | `transpilePackages` в next.config + зависимость | Dockerfile, секреты, зависимость |
| Минусы | копия может устареть; надо не забывать обновлять | код виден всем; сборка зависит от GitHub | сложнее всех, секреты на серверах |

## Как устроена доставка (вариант Б)

- Репозиторий `github.com/kumerovich312-dotcom/chat-kit` — **открытый**. Поэтому в нём нет секретов и нет подробностей
  устройства закрытых проектов (серверы, выкладка, служебные ключи, адреса) — только то, что нужно для набора.
- Каждая версия набора — метка `vX.Y.Z` и выпуск (GitHub Release) с готовым файлом `muras-chat-kit-X.Y.Z.tgz`: внутри
  собранный код (JavaScript + описания типов) и стили. Файл собирается на компьютере разработчика (`npm run release`),
  на сервере ничего не собирается.
- Проект ставит набор ссылкой на этот файл:
  `npm install https://github.com/kumerovich312-dotcom/chat-kit/releases/download/vX.Y.Z/muras-chat-kit-X.Y.Z.tgz`.
  В `package-lock.json` записывается отпечаток файла — `npm ci` на сервере скачивает его по HTTPS без ключей и без git
  и проверяет, что файл тот же.
- В проекте: один раз подключить стили `@muras/chat-kit/styles.css`; окно — из `@muras/chat-kit/ui`; ядро —
  `@muras/chat-kit`; серверная часть — `@muras/chat-kit/server`; подключения — `@muras/chat-kit/nextbot`,
  `@muras/chat-kit/wa-gateway`, `@muras/chat-kit/studio`. Код уже собран — `transpilePackages` в next.config не нужен.
- Обновление: поменять номер версии в ссылке, `npm install`, свои проверки, выкладка по правилам проекта.
- Если GitHub недоступен в момент сборки на сервере — сборка не пройдёт (у Атласа и TishCRM при этом срабатывает откат
  на прежнюю версию); повторить выкладку позже.
