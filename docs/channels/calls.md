# Звонки (телефония)

Звонки клиентов — в той же ленте, что и переписка: входящие и исходящие, разговор или пропущенный, длительность, кто
из команды говорил, запись разговора. Подключение — `@muras/chat-kit/calls`, только для сервера. Два варианта:

- **любая АТС** — общий вебхук JSON (`createCallsAdapter`): АТС или свой скрипт присылает звонок в простом виде;
- **Zadarma** — её собственные уведомления (`createZadarmaAdapter`): ничего писать не нужно, только настроить кабинет.

## Как звонок выглядит в переписке

- Строка с трубкой в ленте клиента: «Входящий звонок · 14:05 · 2:05 · Айгерим», «Пропущенный звонок · 14:05»,
  «Исходящий звонок · 14:10 · 0:45 · Бакыт», «Не дозвонились · 14:12 · Бакыт».
- **Кто говорил** — имя сотрудника по его внутреннему номеру АТС (настройка `managers: { "101": "Айгерим" }`); номера
  нет в списке — имя, которое прислала АТС, иначе «внутр. 101». У пропущенного входящего сотрудника нет.
- **«Ждут ответа»**: пропущенный входящий — клиент ждёт, как если бы написал (с начала звонка); состоявшийся разговор
  (входящий или исходящий) — это ответ; «не дозвонились» ожидание не меняет.
- **Запись разговора** — проигрыватель под строкой звонка. Набор скачивает запись к себе после ответа телефонии и
  прикрепляет её к строке звонка файлом (как голосовое). Окно показывает запись только тем, кому проект передал
  `canListen` (права — дело проекта). Когда проект подключит «розетку ИИ», у записи заработает «Расшифровать»
  (`Attachment.transcript`). Если проект хранит записи не файлом, а ссылкой, — `call.recordUrl` (адрес на своём сайте
  с проверкой прав): окно покажет его, когда у строки нет вложения.
- **Клиент — по номеру телефона.** Звонок встаёт в карточку клиента с тем же номером, даже если тот раньше писал
  в WhatsApp. Новый номер — новый клиент с каналом «Звонок» (`ContactHint`: `source: "calls"`, `externalId` — номер
  в международном виде «+996555000001», `channel: "call"`).
- Скрытый номер и внутренние звонки («101» → «102») в переписку не попадают: карточку не к чему привязать.

## Ответ клиенту

Звонки — только приём. У подключения все возможности (`caps`) выключены — окно не покажет поле ввода для канала
«Звонок», а `send()` вернёт ошибку «Звонки — только приём: отвечайте в мессенджере или перезвоните». Ответить клиенту —
в мессенджере (его подключением) или перезвонить: исходящий звонок придёт строкой сам.

## Вариант 1. Любая АТС — общий вебхук

Годится, если АТС умеет слать вебхук JSON, или у проекта есть свой скрипт или сервис-посредник, который после каждого
звонка делает один запрос.

### Запрос

```
POST https://crm.example/api/calls/events
Content-Type: application/json
Authorization: Bearer <ключ приёма>
```

- Ключ приёма — случайная строка от 16 знаков (лучше от 32), хранится в окружении проекта. Можно прислать и заголовком
  `X-Api-Key: <ключ>`. В адресе (`?key=`) ключ не принимаем: адреса оседают в журналах.
- Один запрос — один звонок, **после его окончания**. Тело — не больше 1 МБ.

### Поля

| Поле | Тип | Нужно | Что это |
|---|---|---|---|
| `id` | строка или число | да | Номер звонка у АТС (до 200 знаков) — ключ повтора: тот же `id` второй раз не запишется |
| `direction` | `"in"` или `"out"` | да | `in` — звонил клиент, `out` — звонили мы (понимаем и `incoming` / `outgoing`) |
| `from` | строка | для `in` | Кто звонил — у входящего это номер клиента |
| `to` | строка | для `out` | Куда звонили — у исходящего это номер клиента |
| `clientPhone` | строка | нет | Номер клиента явно — тогда `from` и `to` не читаем |
| `answered` | `true` / `false` | да | Состоялся ли разговор. Если поля нет — читаем `status` |
| `status` | строка | нет | Итог словами АТС, без учёта регистра: `answered` (или `answer`, `success`, `completed`, `ok`) — разговор; `busy`, `no answer`, `failed`, `cancel` и любое другое — пропущенный. Читаем, только если нет `answered` |
| `startedAt` | строка или число | нет | Начало звонка: ISO 8601 с поясом (`2026-09-27T14:00:00+06:00`, `…Z`) или Unix-время в секундах. Без пояса (`2026-09-27 14:00:00`) — по настройке `timeZone`; нет её или поля — время приёма |
| `durationSec` | число | нет | Длительность разговора в секундах (у пропущенного не показываем) |
| `manager` | `{ "name", "extension" }` | нет | Кто из команды говорил (у исходящего — кто звонил): имя и/или внутренний номер |
| `recordUrl` | строка | нет | Ссылка на запись разговора `https://…` |

Номер — в любом привычном виде: `+996 555 00-00-01`, `996555000001`, `0555 00-00-01` (местный номер читается по коду
страны компании `countryCode`).

Пример:

```json
{
  "id": "a1",
  "direction": "in",
  "from": "+996 555 00-00-01",
  "to": "+996 555 00-00-09",
  "startedAt": "2026-09-27T14:00:00+06:00",
  "answered": true,
  "durationSec": 185,
  "manager": { "name": "Айгерим", "extension": "101" },
  "recordUrl": "https://pbx.example/records/a1.mp3"
}
```

Пропущенный: `{ "id": "a2", "direction": "in", "from": "0555 00-00-01", "startedAt": "2026-09-27T14:05:00+06:00", "answered": false }`.

### Ответы

| Ответ | Когда |
|---|---|
| 200 `{"ok": true, "status": "ok"}` | принято |
| 200 `"status": "duplicate"` | этот `id` уже был — ничего не добавлено |
| 200 `"status": "ignored"` | номер скрыт или внутренний — не записан |
| 400 | тело не JSON или не объект |
| 401 | нет ключа, чужой ключ или ключ приёма не задан в проекте |
| 405 | не POST |
| 413 | тело больше 1 МБ |
| 422 | нет обязательного поля — в `error` сказано, какого |

Повторять запрос стоит при сбое связи и ответах 5xx: повтор безопасен, тот же `id` не задвоится.

### Запись разговора

- Запись готова позже звонка — пришлите **тот же звонок ещё раз** (тот же `id` и поля) с `recordUrl`: строка не
  задвоится, запись прикрепится.
- Ссылка — полная `https://…` (или `http://`), скачивается без входа: временная ссылка или ключ прямо в ссылке.
  Логин и пароль в ссылке (`user:pass@…`) и вход по заголовку не поддерживаются.
- Только звук — mp3, wav, ogg, m4a, amr (тип по содержимому, а не по имени); до 25 МБ (`maxRecordBytes`); не
  с внутренних адресов сервера (localhost, 10.*, 192.168.*). `allowRecordHost` ограничит, откуда можно качать,
  например только адресом своей АТС.
- Запись скачивается один раз, после ответа АТС. Не вышло (ссылка не открылась) — повторите звонок с `recordUrl`.

### Маршрут Next.js

```ts
// src/app/api/calls/events/route.ts
import { after } from "next/server";
import { ingest, jsonResponse, readWebhook } from "@muras/chat-kit/server";
import { createCallsAdapter } from "@muras/chat-kit/calls";

export async function POST(req: Request) {
  const input = await readWebhook(req);
  if (!input) return jsonResponse({ status: 413, body: { ok: false, error: "Слишком большой запрос" } });
  const adapter = createCallsAdapter({
    token: callsToken(),                 // ключ приёма звонков из окружения проекта
    countryCode: "+996",                 // код страны компании
    managers: await staffByExtension(),  // { "101": "Айгерим", … } — из своей таблицы сотрудников
    timeZone: "Asia/Bishkek",            // пояс часов АТС — для startedAt без пояса
  });
  const r = await ingest(adapter, chatStore(orgId), input, {
    later: after, // запись качается после ответа АТС
    hooks: { onContact: async ({ contactId, created }) => { /* новый клиент по звонку → сделка */ } },
  });
  return jsonResponse(r);
}
```

Если у проекта несколько компаний — у каждой свой ключ приёма: найдите компанию по ключу из заголовка (`bearerKey`
из `@muras/chat-kit/server`), затем создайте подключение с её ключом и её переходником.

## Вариант 2. Zadarma

### В кабинете Zadarma

Названия разделов у Zadarma меняются — ищите «API» и «Уведомления о звонках» (webhooks).

1. **Ключ и секрет API.** Создайте ключ (key) и секрет (secret) и положите оба в окружение проекта (только на
   сервере). Секрет обязателен: им Zadarma подписывает уведомления, неподписанные набор не принимает (401). Ключ нужен,
   чтобы получать ссылки на записи разговоров.
2. **Адрес уведомлений о звонках АТС** — `https://crm.example/api/calls/zadarma`. При сохранении Zadarma проверит
   адрес запросом `GET …?zd_echo=<слово>` — маршрут отвечает этим словом (`zadarmaEchoResponse`, пример ниже).
3. **Какие уведомления включить:** `NOTIFY_END` (конец входящего), `NOTIFY_OUT_END` (конец исходящего),
   `NOTIFY_RECORD` (запись готова). Начала звонков (`NOTIFY_START`, `NOTIFY_OUT_START`, `NOTIFY_ANSWER`,
   `NOTIFY_INTERNAL`) не нужны: если включены — набор проверит подпись и пропустит. Уведомления голосового меню, SMS
   и прочие — пропускает, ничего не записывая.
4. **Запись разговоров** — включите в настройках АТС для нужных внутренних номеров (с хранением в облаке). Zadarma
   хранит записи ограниченное время — набор сразу скачивает запись к себе.
5. **Внутренние номера сотрудников** (100, 101…) — сопоставьте с именами в `managers`.
6. **Пояс времени.** `call_start` приходит без пояса, по часам кабинета — укажите тот же пояс в `timeZone`
   («Asia/Bishkek»). Без него начало звонка = приход уведомления минус длительность разговора (неточно на время
   гудков).

### Маршрут Next.js

```ts
// src/app/api/calls/zadarma/route.ts
import { after } from "next/server";
import { ingest, jsonResponse, readWebhook } from "@muras/chat-kit/server";
import { createZadarmaAdapter, zadarmaEchoResponse } from "@muras/chat-kit/calls";

// Проверка адреса при сохранении в кабинете Zadarma: ответить словом из ?zd_echo=
export const GET = (req: Request) => zadarmaEchoResponse(req) ?? new Response("ok");

export async function POST(req: Request) {
  const input = await readWebhook(req);
  if (!input) return jsonResponse({ status: 413, body: { ok: false, error: "Слишком большой запрос" } });
  const store = chatStore(orgId);
  const adapter = createZadarmaAdapter({
    key: zadarmaKey(), secret: zadarmaSecret(), // ключ и секрет API из окружения проекта
    countryCode: "+996",
    managers: await staffByExtension(),
    timeZone: "Asia/Bishkek",                   // тот же пояс, что в кабинете Zadarma
    state: store.state,                         // помнить звонок, пока Zadarma готовит запись
  });
  return jsonResponse(await ingest(adapter, store, input, { later: after }));
}
```

### Как приходит запись

1. `NOTIFY_END` / `NOTIFY_OUT_END` с `is_recorded=1` — строка звонка появляется сразу, а сам звонок (номер клиента,
   направление, время) запоминается в `state`: в уведомлении о записи номера клиента нет.
2. `NOTIFY_RECORD` — после ответа Zadarma набор запрашивает временную ссылку у API
   (`GET https://api.zadarma.com/v1/pbx/record/request/?call_id=…&format=json`, заголовок
   `Authorization: <ключ>:<подпись>`), скачивает файл (до 25 МБ, только звук) и прикрепляет к строке звонка.
3. Уведомления пришли не по порядку (запись раньше конца звонка) — набор запомнит запись и прикрепит её, как только
   придёт конец звонка.

`state` — «ключ → значение» проекта (`ChatStore.state`): одна короткая строка на каждый звонок с записью, через сутки
её можно удалять. Без `state` — память процесса: годится для одного постоянно работающего сервера, но не для
нескольких копий сервера или «бессерверного» хостинга — конец звонка и запись попадут в разные копии, и запись
не прикрепится.

Скачать запись ещё раз (например, для кнопки «обновить запись») — `zadarmaRecordingLink({ key, secret, callId })`
вернёт свежую ссылку.

### Подпись (для проверки и отладки)

- Уведомление: заголовок `Signature` = base64 от **шестнадцатеричной** записи HMAC-SHA1 строки подписи секретом API
  (как `base64_encode(hash_hmac('sha1', …))` в PHP).
- Строка подписи — поля подряд, у каждого уведомления свои:

| Уведомление | Строка подписи |
|---|---|
| `NOTIFY_START`, `NOTIFY_INTERNAL`, `NOTIFY_END` | `caller_id` + `called_did` + `call_start` |
| `NOTIFY_ANSWER` | `caller_id` + `destination` + `call_start` |
| `NOTIFY_OUT_START`, `NOTIFY_OUT_END` | `internal` + `destination` + `call_start` |
| `NOTIFY_RECORD` | `pbx_call_id` + `call_id_with_rec` |

- Запрос к API: `Authorization: <ключ>:<base64(hex(HMAC-SHA1(путь + параметры + md5(параметры))))>`, параметры — по
  алфавиту, как PHP `http_build_query`.

## Номер звонящего — «подлинный»

Номер клиента в звонке определяет телефонная сеть, а не называет собеседник, поэтому подключение отмечает его
подлинным (`phoneTrusted: true`): звонок встаёт в карточку уже известного клиента с этим номером. Оговорка: номер
можно подделать (так делают недобросовестные операторы IP-телефонии). Что это даёт подделавшему — только строку
звонка в чужой карточке; переписку он не получает: звонки только принимаются. Если для проекта и это важно — переходник
может не склеивать клиентов по номеру из звонка (`hint.source === "calls"`) и заводить отдельную карточку.

## Личные данные

Записи разговоров — персональные данные: голос и всё, что клиент сказал.

- Храните записи у себя и отдавайте только сотрудникам, которым можно: `canListen` в окне и проверка прав на адресе
  файла. Не открывайте записи по ссылке без входа и не пересылайте их клиенту в мессенджер.
- Срок хранения и удаление по просьбе клиента — по правилам компании и закону страны; клиента предупреждают о записи
  (обычно — голосовым приветствием АТС).
- Ключ приёма, ключ и секрет Zadarma — только в окружении сервера; в журналы их, ссылки на записи и тела уведомлений
  не пишите (в ссылках на записи — ключи доступа).

## Ограничения

- Только приём: позвонить клиенту из CRM (кнопкой) пока нельзя.
- Одна запись на звонок: при переводе звонка у Zadarma записей несколько — прикрепляется первая пришедшая.
- Запись скачивается один раз после уведомления; не вышло — повтор уведомления (или звонка с `recordUrl`) попробует
  снова.
- Zadarma закрывает подписью только часть полей: перехваченное уведомление можно повторить с другой длительностью,
  итогом или номером звонка. Держите адрес только на https и не пишите тела уведомлений в открытые журналы; при
  желании — пускайте на адрес только серверы Zadarma (их адреса — в её документации) на уровне прокси.
- Звонок, который принял автоответчик или голосовое меню, Zadarma может прислать с итогом `answered` — тогда он
  считается разговором.
- Общий вебхук: один звонок на запрос; записи, которые скачиваются только со входом, не поддерживаются.

## Проверка после подключения

- Позвоните на номер компании и не берите трубку — в ленте «Пропущенный звонок», клиент в «Ждут ответа».
- Перезвоните ему — «Исходящий звонок · … · имя», клиент ушёл из «Ждут ответа».
- Через минуту после разговора с записью — под строкой звонка проигрыватель (у тех, кому можно слушать).
- Повторная отправка того же звонка — строка одна.
