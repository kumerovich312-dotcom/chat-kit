# WhatsApp через GREEN-API

Подключение `@muras/chat-kit/green-api`: номер WhatsApp компании работает через сервис GREEN-API (green-api.com), CRM
получает сообщения клиентов и отвечает им. Код — `src/channels/green-api`, проверки — `tests/channels/green-api`.

## Сначала о рисках

- **Это не официальный WhatsApp.** GREEN-API подключает номер как «связанное устройство» — так же, как WhatsApp Web.
  Официального договора с WhatsApp нет, поэтому **номер могут заблокировать**: за массовые рассылки, за первые
  сообщения тем, кто не ждал, за жалобы, за резкий рост переписки на новом номере. Номер — только для ответов клиентам
  и сообщений тем, кто сам просил; рассылки — не с него.
- **Тариф платный.** Бесплатный тариф GREEN-API (Developer) пишет только в 3 чата в месяц — он годится для проверки,
  не для работы. Для работы нужен платный тариф инстанса.
- **Переписка идёт через серверы GREEN-API.** Это посредник с доступом к сообщениям клиентов — упомяните его в
  политике обработки персональных данных.
- **Телефон с WhatsApp должен оставаться в строю.** Если WhatsApp на телефоне отвяжет устройство или телефон долго
  без интернета, сообщения перестанут приходить — подключение сообщит об этом (`onAlert`, раздел 5).

## 1. Кабинет GREEN-API

1. Зарегистрироваться на console.green-api.com и создать **инстанс** (подключение одного номера WhatsApp).
2. В карточке инстанса взять: `idInstance` (номер инстанса), `apiTokenInstance` (ключ инстанса), `apiUrl` и
   `mediaUrl` (адреса API вида `https://1100.api.greenapi.com` и `https://1100.media.greenapi.com`).
3. Привязать номер: в кабинете открыть QR-код, на телефоне — WhatsApp → Настройки → Связанные устройства →
   Привязка устройства, отсканировать.
4. Настройки инстанса (или одной командой — раздел 6):
   - адрес уведомлений (`webhookUrl`) — маршрут проекта, например `https://<сайт>/api/whatsapp/green-api`;
   - токен уведомлений (`webhookUrlToken`) — придумать случайный ключ от 16 знаков (например, `openssl rand -hex 32`);
     GREEN-API присылает его в заголовке `Authorization: Bearer <ключ>`, без него подключение отвечает 401;
   - включить уведомления: входящие сообщения и файлы (`incomingWebhook`), статусы отправленных (`outgoingWebhook`),
     сообщения с телефона (`outgoingMessageWebhook`), сообщения через API (`outgoingAPIMessageWebhook`), состояние
     инстанса (`stateWebhook`), входящие звонки (`incomingCallWebhook`), опросы (`pollMessageWebhook`), изменённые и
     удалённые сообщения (`editedMessageWebhook`, `deletedMessageWebhook`);
   - **не** включать «отмечать входящие прочитанными» (`markIncomingMessagesReaded`) — иначе клиент увидит синие
     галочки раньше, чем сообщение прочитал менеджер;
   - режим `@lid` (`enableLidMode`) не включать: в нём вместо номера клиента приходит скрытый адрес — телефона не будет.

## 2. Что проект хранит в окружении

Номер инстанса, ключ инстанса, `apiUrl`, `mediaUrl` и ключ вебхука — только в окружении проекта (или в своей таблице
настроек компании), не в коде и не в репозитории. Названия переменных — на выбор проекта.

## 3. Приём уведомлений (маршрут Next.js)

```ts
// src/app/api/whatsapp/green-api/route.ts
import { after } from "next/server";
import { createGreenApiAdapter } from "@muras/chat-kit/green-api";
import { ingest, jsonResponse, readWebhook } from "@muras/chat-kit/server";
import { chatStore } from "@/lib/chat-store";

// Доступ к инстансу — из окружения проекта (названия переменных — любые)
export function whatsapp() {
  return createGreenApiAdapter({
    idInstance: process.env.WA_INSTANCE_ID ?? "",
    apiTokenInstance: process.env.WA_INSTANCE_TOKEN ?? "",
    apiUrl: process.env.WA_API_URL ?? "",
    mediaUrl: process.env.WA_MEDIA_URL,
    webhookToken: process.env.WA_WEBHOOK_TOKEN ?? "",
    onAlert: (a) => saveChannelAlert(a), // баннер администратору: «WhatsApp не подключён — отсканируйте QR…»
  });
}

export async function POST(req: Request) {
  const input = await readWebhook(req);
  if (!input) return jsonResponse({ status: 413, body: { ok: false, error: "Слишком большое уведомление" } });
  const r = await ingest(whatsapp(), chatStore(ORG_ID), input, { later: after }); // файлы — после ответа GREEN-API
  return jsonResponse(r);
}
```

Несколько компаний, у каждой свой номер: компанию находят по номеру инстанса из уведомления —
`greenApiInstanceId(input.body)` → своя таблица «инстанс → компания, доступ, ключ вебхука» → подключение с этими
настройками (ключ вебхука подключение всё равно проверит само). Или адрес с ключом компании:
`/api/whatsapp/green-api/[org]`.

Что стоит знать о приёме:
- GREEN-API повторяет уведомление раз в минуту, пока сервер не ответит 200 (до суток). Повтор распознаётся по ключу
  сообщения `ga:<idMessage>` — второй раз не записывается.
- Всё ненужное (группы, статусы WhatsApp, `deviceInfo`, звонок, который ещё идёт) — ответ 200 и `summary.status =
  "ignored"` с причиной в `summary.error`.
- Клиент заводится по адресу чата (`ContactHint`: `source: "green-api"`, `externalId: "996555000001@c.us"`,
  `channel: "whatsapp"`, телефон `+996555000001`, `phoneTrusted: true` — номер из WhatsApp подлинный, по нему можно
  привязать переписку к уже известному клиенту). Имя — как клиент подписан в WhatsApp, иначе как записан в телефоне
  компании.

## 4. Ответ клиенту

```ts
// серверное действие: сообщение уже записано в базу с delivery = 'pending'
const r = await whatsapp().send(
  { externalId: client.whatsappChatId ?? client.phone }, // «996555000001@c.us» или «+996555000001» (написать первым)
  {
    text,
    author: { type: "operator_crm", name: user.name, id: String(user.id) }, // у бота — { type: "bot" }
    replyTo: quoted ? { externalId: quoted.externalId } : null, // цитата: ключ «ga:…» исходного сообщения
    file, // { name, mime, url } — ссылка на сайт проекта (signFileLink) или { name, mime, data } — содержимое
  },
);
await updateMessage(id, r.ok ? { delivery: "sent", externalId: r.externalId } : { delivery: "failed", deliveryError: r.error });
```

- **Сохраните `r.externalId`** (`ga:<idMessage>`) у своего сообщения: по нему придут галочки, а «эхо» этой отправки
  (GREEN-API присылает её уведомлением `outgoingAPIMessageReceived`) не запишется второй раз.
- Ответ бота пишется разметкой Markdown — подключение переводит её в разметку WhatsApp (`*жирный*`, `_курсив_`).
  Текст менеджера уходит как набран.
- Файл по ссылке: GREEN-API забирает его сам, ссылка должна открываться из интернета (адрес сайта, не localhost) и
  жить хотя бы несколько минут (`signFileLink` — сутки). Имя файла — с расширением (без него подключение допишет его
  по типу). Текст при файле уходит подписью (до 1024 знаков).
- Ошибка — короткой причиной по-русски: «WhatsApp не подключён — отсканируйте QR в кабинете GREEN-API», «Закончился
  лимит тарифа GREEN-API…», «GREEN-API не принял ключ инстанса…». `retryable: true` (нет связи, 429, 5xx) — можно
  повторить позже, но не больше 1–2 раз: у GREEN-API нет ключа повтора, и если сообщение всё-таки ушло, повтор
  дойдёт клиенту дважды.
- Статусы могут прийти не по порядку («прочитано» раньше «дошло») — в `updateMessage` не понижайте статус
  (`DELIVERY_RANK` из ядра).

## 5. Что попадает в переписку

| От GREEN-API | В CRM |
|---|---|
| Сообщение клиента: текст, ссылка, ответ с цитатой | сообщение клиента, клиент «ждёт ответа»; цитата ведёт к исходному сообщению |
| Фото, видео, голосовое, документ, стикер | подпись — сообщением, файл — вложением следом (скачивается после ответа GREEN-API; устаревшую ссылку подключение заменит свежей через `downloadFile`) |
| Геопозиция, контакт, опрос, голос в опросе, нажатая кнопка, пункт списка | текстом: «Геопозиция: … — ссылка на карту», «Контакт: имя, телефон», «Ответ в опросе «…»: …» |
| Незнакомый вид сообщения | «Сообщение WhatsApp такого вида CRM пока не показывает — посмотрите его в телефоне» (клиент не теряется) |
| Сообщение с телефона компании | автор «менеджер с телефона»; это ответ клиенту |
| Сообщение через API | своё (из `send`) — не дублируется; чужое (другая программа на том же номере) — от «бота» |
| Статус | ушло, дошло, прочитано; «не доставлено» с причиной («У этого номера нет WhatsApp») |
| Входящий звонок | строка звонка, когда известен итог: пропущенный или отклонённый — клиент ждёт ответа, принятый — ответ |
| Исходящий звонок с телефона | строка звонка с длительностью или «Не дозвонились» |
| Реакция клиента | служебная строка «Клиент отреагировал на сообщение: …» — ответа не ждёт; снятая реакция — пропуск |
| Клиент исправил сообщение | новая запись «Исправлено: …» с цитатой исходного — видно, что было и что стало |
| Мы исправили сообщение | служебная строка с новым текстом |
| Удалённое сообщение | служебная строка; само сообщение в CRM остаётся |
| WhatsApp отключён / снова подключён / заблокирован, закончился лимит тарифа | в переписку не пишется: `onAlert({ type, state, ok, text, at })` — показать администратору; тот же текст — в `summary.meta.alert` |
| Группы, статусы WhatsApp, каналы | пропускаются; группы включаются `groups: true` (группа — один диалог, автор — участник по имени) |

## 6. Проверка связи и настройка одной командой

```ts
import { greenApiSetSettings, greenApiState } from "@muras/chat-kit/green-api";

const access = { idInstance, apiTokenInstance, apiUrl, mediaUrl }; // из окружения проекта
await greenApiState(access); // { ok: true, state: "notAuthorized", authorized: false, text: "WhatsApp не подключён — отсканируйте QR…" }
await greenApiSetSettings({ ...access, webhookUrl: "https://<сайт>/api/whatsapp/green-api", webhookUrlToken }); // нужные уведомления
```

`greenApiSetSettings` включает уведомления из раздела 1 и выключает «отмечать прочитанными»; остальные настройки
инстанса не трогает (свои — в `extra`). Прочие методы GREEN-API — `greenApiRequest(access, "метод", { body })`.

## Ограничения

- Паузы бота и «не отвечать этому клиенту» нет (`caps.pause = false`, `caps.mute = false`): это просто номер WhatsApp,
  бота в нём нет. Написать первым можно (`caps.start = true`).
- Пределы GREEN-API: текст — до 20 000 знаков, подпись к файлу — до 1024, файл — до 100 МБ. Длиннее — ошибка до
  отправки.
- Принятые файлы набор сохраняет до 10 МБ (`maxFileBytes`) и только известных типов (фото, видео, голосовые, PDF,
  Word, Excel). Если файл не сохранился, а подписи у него не было, в переписке от этого сообщения ничего не останется —
  проекту, который хранит большие видео, стоит поднять `maxFileBytes`.
- Звонки — только факт (принят, пропущен, длительность исходящего); записи разговора у WhatsApp нет. Какой настройкой
  GREEN-API включаются уведомления об исходящих звонках (`outgoingCall`), в документации не сказано — если их нет,
  исходящих звонков в ленте не будет.
- Галочки у файла без подписи, отправленного с телефона компании, не показываются: статус приходит на номер
  сообщения, а файл записан под своим номером.
- Если «эхо» отправки придёт раньше, чем проект сохранил `externalId` у своего сообщения, сообщение задвоится.
  На деле GREEN-API отправляет с задержкой (очередь инстанса), и эхо приходит позже ответа `send`.
- Режим `@lid`: личный чат без телефона — клиент заводится без номера и не привязывается к известному клиенту по
  телефону.
