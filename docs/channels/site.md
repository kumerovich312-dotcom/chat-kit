# Чат на сайте

Кнопка чата в углу сайта компании. Посетитель пишет — сообщение приходит в CRM как обычный диалог (канал `site`,
«Чат на сайте»); менеджер отвечает из окна переписки — посетитель видит ответ в том же окошке на сайте.

Две части:
- **сервер** — `@muras/chat-kit/site`: один маршрут проекта `handleSiteRequest` и подключение `createSiteAdapter`;
- **виджет** — один файл без зависимостей `dist/widget/chat-widget.js` (исходник `src/widget/chat-widget.ts`): проект
  отдаёт его со своего сайта, компания ставит одну строку `<script>` на свой сайт.

```
сайт компании: виджет (Shadow DOM)          CRM проекта
  «start»  — номер посетителя и ключ ──────▶ /api/site-chat/start    ─┐
  «message» — сообщение, файл base64 ──────▶ /api/site-chat/message  ─┼─ handleSiteRequest → ingest → переходник
  «messages?after=» — раз в 3 с ◀────────── /api/site-chat/messages  ─┘  (history проекта: что посетителю видно)
```

## 1. Секрет

Секрет чата на сайте — в окружении проекта (имя переменной — на выбор проекта), длинный случайный, отдельный от ключей
каналов и от секрета ссылок на файлы. Сделать:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Из секрета сервер подписывает номер каждого посетителя (ключ = HMAC-SHA256(секрет, номер)); хранить ключи не нужно.
Секрет короче 16 знаков или пустой — чат отвечает 500 «Чат на сайте не настроен», в журнале сервера — что поправить.
Сменили секрет — прежние ключи не подходят: виджеты сами начнут новый чат (переписка в CRM остаётся, но посетитель её
больше не увидит).

## 2. Маршрут в проекте (Next.js)

Один файл с необязательным «хвостом» адреса — `[[...path]]`, тогда проверка связи работает и на `/api/site-chat`:

```ts
// src/app/api/site-chat/[[...path]]/route.ts
import { handleSiteRequest } from "@muras/chat-kit/site";
import { signFileLink } from "@muras/chat-kit/server";
import { chatStore } from "@/lib/chat-store";          // переходник проекта (docs/CONNECT.md)
import { siteHistory } from "@/lib/site-history";

const ORG = 1; // у CRM с несколькими компаниями — компания из адреса: /api/site-chat/<ключ сайта>/…

async function handle(req: Request) {
  return handleSiteRequest(req, {
    secret: process.env.SITE_CHAT_SECRET ?? "",        // секрет из окружения проекта
    store: chatStore(ORG),
    history: (contactId, afterId) => siteHistory(ORG, contactId, afterId),
    // Посетитель не вошёл в CRM — файлы ему только по подписанной ссылке (на сутки)
    fileUrl: (att) => signFileLink({ origin: "https://crm.example.kg", path: `/files/${att.id}`, id: att.id, secret: process.env.FILE_LINK_SECRET ?? "" }),
    origins: ["https://example.kg", "https://www.example.kg"], // сайты, где стоит виджет
    phoneCode: "+996",                                  // номер из формы «0555 …» → «+996555…»
    showAgentNames: true,                               // «Айгерим · 14:05» под ответом
    hooks: { onContact: async ({ contactId, created }) => { if (created) { /* новое обращение → своя заявка */ } } },
  });
}
export { handle as GET, handle as POST, handle as OPTIONS };
```

Действие — последняя часть адреса: `POST …/start`, `POST …/message`, `GET …/messages?after=<номер>`, остальные
`GET` — проверка связи (`{ ok: true, service: "чат на сайте" }`).

`history` — сообщения диалога из своей базы, **по порядку**, после сообщения `afterId` (без него — последние, до 100).
Отдавайте всё подряд тем же переводом в `ChatMessage`, что и для окна переписки: что посетителю можно видеть, набор
отберёт сам.

```ts
// src/lib/site-history.ts — образец; таблицы и поля у проекта свои
export async function siteHistory(orgId: number, contactId: string, afterId: string | null) {
  const rows = afterId
    ? await sql`SELECT * FROM messages WHERE org_id = ${orgId} AND client_id = ${contactId} AND id > ${afterId} ORDER BY id LIMIT 200`
    : await sql`SELECT * FROM (SELECT * FROM messages WHERE org_id = ${orgId} AND client_id = ${contactId} ORDER BY id DESC LIMIT 100) t ORDER BY id`;
  return rows.map(toChatMessage);
}
```

Переходник получает посетителя как `ContactHint`:

| Поле | Значение |
|---|---|
| `source` | `"site"` |
| `externalId` | номер посетителя `v_…` (его и хранить как адрес клиента у подключения: `site:v_…`) |
| `channel` | `"site"` |
| `name`, `phone`, `email` | из формы перед чатом, если посетитель её заполнил |
| `phoneTrusted` | всегда `false` |

**Не склеивайте посетителя с известным клиентом по телефону или почте из формы** — их никто не проверял: посторонний
назвал бы чужой номер и увидел бы чужую переписку. Объединить может менеджер руками.

Необязательно: `findContact(hint)` — найти клиента, не заводя нового (для опроса «есть ли ответ»). Без него опрос
зовёт `findOrCreateContact` — виджет спрашивает ответы, только когда посетитель уже писал или представился, так что
пустых клиентов не бывает, если сайт не подделывает запросы.

## 3. Отдать виджет со своего сайта

Файл виджета лежит в пакете: `node_modules/@muras/chat-kit/dist/widget/chat-widget.js`. Проще всего копировать его в
`public/` при установке — строка в `scripts` в `package.json` проекта:

```json
"postinstall": "node -e \"require('fs').copyFileSync('node_modules/@muras/chat-kit/dist/widget/chat-widget.js','public/chat-widget.js')\""
```

Виджет — модуль (`type="module"`): с чужого сайта браузер загрузит его, только если сервер разрешит (CORS). В
`next.config`:

```ts
async headers() {
  return [{ source: "/chat-widget.js", headers: [
    { key: "Access-Control-Allow-Origin", value: "*" },
    { key: "Cache-Control", value: "public, max-age=3600" },
  ] }];
}
```

## 4. Код для сайта компании

Одна строка перед `</body>`:

```html
<script type="module" src="https://crm.example.kg/chat-widget.js"
  data-endpoint="https://crm.example.kg/api/site-chat"
  data-title="Напишите нам" data-color="#2563eb"
  data-greeting="Здравствуйте! Чем помочь?" data-position="right"></script>
```

| Атрибут | Что делает |
|---|---|
| `data-endpoint` | адрес маршрута из п. 2 (обязательно). Относительный — от адреса самого скрипта |
| `data-title` | заголовок панели («Напишите нам») |
| `data-color` | главный цвет (кнопка, шапка, пузырь посетителя); цвет текста на нём подберётся сам |
| `data-greeting` | приветствие в начале переписки; `data-greeting=""` — без приветствия |
| `data-position` | `right` (по умолчанию) или `left` |
| `data-prechat` | форма перед чатом: `name,phone`, `name,email`, `name,phone,email` или `true` (имя и телефон) |
| `data-prechat-required` | `true` — форму не пропустить: имя и телефон или почта (хватит одного) |
| `data-open` | `true` — панель открыта сразу |

Свой сайт на React — без тега, вызовом:

```ts
import { mountChatWidget } from "@muras/chat-kit/widget";

useEffect(() => {
  const chat = mountChatWidget({ endpoint: "https://crm.example.kg/api/site-chat", title: "Напишите нам", preChat: { fields: ["name", "phone"], required: true } });
  return () => chat.destroy();
}, []);
```

Там же: `texts` — свои слова вместо русских по умолчанию (`WIDGET_TEXTS`), `theme` — внешний вид, `open()`, `close()`,
`refresh()` (спросить новые сообщения сейчас).

## 5. Как ответ доходит до посетителя

Менеджер отвечает в окне переписки как обычно — канал диалога `site`. Серверное действие проекта записывает ответ в
базу и отправляет его через подключение:

```ts
import { createSiteAdapter } from "@muras/chat-kit/site";

const site = createSiteAdapter({ secret: process.env.SITE_CHAT_SECRET ?? "" });
const r = await site.send({ externalId: visitorId, contactId }, { text, author }); // { ok: true, externalId: null }
```

`send` ничего не шлёт по сети: ответ уже в базе проекта, виджет заберёт его сам — раз в 3 секунды, пока чат открыт,
раз в 20 секунд, пока свёрнут (тогда на кнопке — значок непрочитанных). Статусов «доставлено / прочитано» нет, написать
первым нельзя (`caps`: текст и файлы — да, статусы, пауза, «не отвечать», «написать первым» — нет).

Посетитель видит только свои сообщения из виджета и ваши ответы в канале `site`. Не видит: заметки команды, служебные
строки, звонки, черновики бота, недоставленное (`delivery: "failed"`), переписку из других каналов, сообщения,
внесённые менеджером за клиента. Ответ бота (Markdown) показывается чистым текстом, ссылки нажимаются. Имя сотрудника —
только первое слово и только с `showAgentNames`; подпись бота — `botName`. Файл менеджера посетитель откроет по
ссылке из `fileUrl`; без `fileUrl` видно только имя файла.

## 6. Что приходит в CRM

- Сообщение посетителя — автор `client`, канал `site`, ключ повтора `site:<посетитель>:<номер сообщения у виджета>`:
  повтор после обрыва связи второй раз не записывается. Клиент «ждёт ответа», вкладки узнают через `notify`.
- Один раз на посетителя — служебная строка:
  «Чат на сайте: страница https://example.kg/prices · пришёл с google.com · метки: utm_source=google · представился:
  Айгерим, +996 555 00-00-01». Из адресов — только страница и метки `utm_*`: остальные параметры (ключи сброса пароля,
  номера заказов) в CRM не попадают.
- Форма перед чатом заполнена — клиент заводится сразу, до первого сообщения (с этой строкой).
- Файл — отдельным сообщением сразу за текстом: фото, PDF, Word и Excel (docx, xlsx), аудио; тип — по содержимому,
  имя — без папок. Файлы с сайта записываются до ответа виджету (качать их не нужно — они уже в запросе).

## 7. Защита

- Ключ посетителя в каждом запросе (`Authorization: Bearer <номер>.<ключ>`), сравнение за одно и то же время; чужой
  номер с чужим ключом — 401.
- CORS: только сайты из `origins` и сам сайт CRM; чужой сайт — 403 (и на предварительной проверке, и на простом
  запросе). `"*"` — любой сайт, только для проверок. «Сам сайт CRM» узнаётся по адресу запроса: если сервер за прокси
  видит внутренний адрес (`http://localhost:3000`), а виджет стоит на страницах самой CRM — добавьте в `origins` и её
  публичный адрес.
- Частота (в памяти процесса, `limits`): 20 сообщений в минуту от посетителя, 60 — с адреса IP, 60 опросов в минуту от
  посетителя, 30 новых посетителей в час с адреса, 600 запросов в минуту с адреса; сверх — 429 и `Retry-After`. Адрес —
  первый из `X-Forwarded-For` (его ставит прокси перед сервером). Сервер без прокси — передайте свой способ: `ip: (req) => …`.
- Сообщение — до 4000 знаков, без управляющих знаков и переключателей направления письма; файл — до 5 МБ (`maxFileBytes`).
- Виджет вставляет текст только как текст: `<img onerror>` в сообщении остаётся буквами; ссылки — только http и https,
  с `rel="noopener noreferrer"`.

## 8. Внешний вид

Всё — переменными `--ckw-*` (значения по умолчанию — `WIDGET_THEME` в `src/widget/chat-widget.ts`). Задать можно
через `theme` в `mountChatWidget`, `data-color` или CSS самого сайта:

```css
ck-chat-widget { --ckw-accent: #16a34a; --ckw-accent-ink: #ffffff; --ckw-radius: 12px; }
```

| Переменная | Что это |
|---|---|
| `--ckw-accent`, `--ckw-accent-ink` | главный цвет и текст на нём |
| `--ckw-background`, `--ckw-surface` | фон панели и фон ленты |
| `--ckw-text`, `--ckw-muted`, `--ckw-border` | текст, подписи, линии |
| `--ckw-company-bubble`, `--ckw-company-ink` | пузырь ответа компании |
| `--ckw-visitor-bubble`, `--ckw-visitor-ink` | пузырь посетителя |
| `--ckw-link`, `--ckw-danger` | ссылки, ошибки |
| `--ckw-notice`, `--ckw-notice-ink` | полоса «нет связи» |
| `--ckw-badge`, `--ckw-badge-ink`, `--ckw-online` | значок непрочитанных, точка «онлайн» |
| `--ckw-font`, `--ckw-font-size` | шрифт |
| `--ckw-radius`, `--ckw-bubble-radius` | скругления |
| `--ckw-launcher-size`, `--ckw-panel-width`, `--ckw-panel-height`, `--ckw-offset` | размеры и отступ от края |
| `--ckw-shadow`, `--ckw-z-index` | тень, «поверх всего» |

Цвет задан через CSS сайта, а не `data-color`, — задайте и `--ckw-accent-ink` (сам он подбирается только для
`data-color` и `theme.accent`). На экране уже 480 px панель — во весь экран.

«Онлайн» в шапке: `online: () => …` в маршруте (например, рабочие часы) — при `false` виджет пишет «ответим, как только
сможем». Без `online` — всегда «онлайн». Функция зовётся при каждом опросе — пусть будет быстрой (без запросов к базе
или с запоминанием на минуту).

## 9. Ограничения

- Ответ появляется не мгновенно: виджет спрашивает раз в 3 секунды (открыт) или 20 секунд (свёрнут), вкладка скрыта —
  не спрашивает. Живого соединения (WebSocket, SSE) нет, «печатает…» и «прочитано» — тоже.
- Посетитель — это браузер: номер и ключ в `localStorage`. Другой браузер или телефон — новый посетитель; браузер
  запретил хранилище — помнит до перезагрузки страницы.
- Счётчики частоты — в памяти процесса: на нескольких серверах и в serverless у каждого свои (защита от баловства,
  не от атаки — ту ставят перед сервером).
- Файл идёт в запросе base64 — на треть больше самого файла. На Vercel запрос не больше 4,5 МБ — ставьте
  `maxFileBytes: 3 * 1024 * 1024`.
- Старые `.doc` и `.xls`, видео, архивы — не принимаются.
- `NewFile.sourceUrl` у файла посетителя — строка `data:…` с самим файлом: не храните её в базе (или сохраняйте
  `null`, если строка начинается с `data:`).

## Проверка

- Демо-страница набора: `/widget/` на демо-сервере (порт 30030) — «сайт компании» с виджетом, пульт: цвет, сторона,
  форма перед чатом, «на связи», ответ менеджера (текст, фото, файл, голосовое, ссылка). Сервер там ненастоящий.
- Тесты: `tests/channels/site/server.test.ts` (маршрут, ключи, CORS, частота, размеры, повторы, что видно посетителю,
  файлы) и `tests/channels/site/widget.dom.test.ts` (виджет в jsdom против настоящего маршрута).
- После подключения: написать с сайта → клиент в «Ждут ответа», строка «Чат на сайте: страница …»; ответить из CRM →
  ответ в виджете за 3 секунды; свернуть виджет и ответить → значок на кнопке; с чужого сайта — 403.
