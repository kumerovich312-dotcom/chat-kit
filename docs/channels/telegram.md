# Telegram-бот

Подключение `@muras/chat-kit/telegram` (только для сервера): клиент пишет боту компании в Telegram — сообщение
появляется в переписке CRM; менеджер отвечает из CRM — клиент получает ответ от бота. Работает через официальный
Bot API Telegram, бесплатно. Код — `src/channels/telegram`, проверки — `tests/channels/telegram`.

## Что умеет

| | |
|---|---|
| Входящие | текст (у слов-ссылок адрес дописывается в скобках); фото (самый большой размер), документы, голосовые, аудио, видео, «кружки», GIF — файлами; стикер, геопозиция, место, контакт, кубик, опрос — текстом; ответ с цитатой; пересланное — с пометкой «Переслано от …»; кнопка «Старт» и метка ссылки |
| Служебные строки | клиент изменил сообщение; клиент заблокировал или разблокировал бота |
| Исходящие | текст: ответ бота — с разметкой, текст менеджера — как набран, длинный — частями; ответ с цитатой; файл — фото, голосовое, аудио, видео, документ, с подписью |
| Нельзя | написать клиенту первым; статусы «доставлено» и «прочитано»; пауза бота и «не отвечать»; группы и каналы (по умолчанию) |

## 1. Создать бота

1. В Telegram открыть **@BotFather** → команда `/newbot` → название (его видят клиенты) → ник бота, который
   заканчивается на `bot` (например, `company_help_bot`).
2. BotFather пришлёт **ключ бота** (токен) вида `123456789:AA…`. Это пароль: у кого ключ — тот управляет ботом.
3. По желанию там же: `/setuserpic` — картинка, `/setdescription` — что бот умеет (клиент видит до «Старта»),
   `/setjoingroups` → Disable — чтобы бота нельзя было добавить в группы.
4. Ключ утёк — `/revoke` в BotFather: старый перестанет работать; новый — в окружение проекта и заново подключить
   вебхук (раздел 3).

## 2. Что проект хранит в окружении

- **ключ бота** из BotFather;
- **секрет вебхука** — придумать случайную строку от 32 знаков из латинских букв, цифр, `_` и `-` (например,
  `openssl rand -hex 32`). Telegram присылает его в заголовке `X-Telegram-Bot-Api-Secret-Token` каждого уведомления;
  без него или с чужим подключение отвечает 401 и ничего не записывает.

Названия переменных — на выбор проекта. Несколько компаний — у каждой свой бот: ключ и секрет — в своей таблице
настроек (зашифрованными), адрес вебхука — с номером компании (раздел 4).

## 3. Подключить вебхук

Один раз, и заново — после смены адреса, секрета или ключа. Удобно сделать кнопкой «Подключить Telegram» в настройках
проекта:

```ts
import { telegramGetMe, telegramSetWebhook, telegramWebhookInfo } from "@muras/chat-kit/telegram";

const me = await telegramGetMe({ token });         // { ok: true, bot: { id, username, name } } — ключ верный
const r = await telegramSetWebhook({ token, secretToken, url: "https://<сайт>/api/telegram/webhook" });
if (!r.ok) throw new Error(r.error);               // причины — по-русски
```

- Адрес — только **https**, открытый из интернета, порт 443, 80, 88 или 8443. Адрес на компьютере разработчика
  (`localhost`) Telegram не достанет — для проверки нужен публичный адрес (туннель) или стенд.
- Telegram присылает только нужное: сообщения, правки, «заблокировал / разблокировал» (`TELEGRAM_UPDATES`).
  `dropPendingUpdates: true` — забыть уведомления, накопившиеся, пока вебхук не работал.
- **У бота один вебхук**: новый адрес заменяет старый. Для стенда проверок — отдельный бот.
- Проверка: `telegramWebhookInfo({ token })` → `url`, `pending` (сколько уведомлений ждут), `lastError` — последняя
  ошибка доставки словами Telegram (например, `Wrong response from the webhook: 401 Unauthorized` — секрет в Telegram
  и у проекта разный). Отключить — `telegramDeleteWebhook({ token })`.

## 4. Маршрут приёма (Next.js)

```ts
// src/app/api/telegram/webhook/route.ts
import { after } from "next/server";
import { createTelegramAdapter } from "@muras/chat-kit/telegram";
import { ingest, jsonResponse, readWebhook } from "@muras/chat-kit/server";
import { chatStore } from "@/lib/chat-store";

const env = (name: string) => process.env[name] ?? ""; // названия — любые

export async function POST(req: Request) {
  const input = await readWebhook(req);
  if (!input) return jsonResponse({ status: 413, body: { ok: false, error: "Слишком большой запрос" } });
  const adapter = createTelegramAdapter({ token: env("TELEGRAM_BOT_TOKEN"), secretToken: env("TELEGRAM_WEBHOOK_SECRET") });
  try {
    return jsonResponse(await ingest(adapter, chatStore(ORG_ID /* своя компания */), input, { later: after }));
  } catch (e) {
    console.error("[telegram] ошибка приёма:", e);
    // Telegram повторит уведомление позже — второй раз сообщение не запишется
    return jsonResponse({ status: 500, body: { ok: false } });
  }
}
```

- `later: after` — файлы скачиваются после ответа Telegram: сообщение видно сразу, фото — через секунду.
- Telegram ждёт ответа и повторяет уведомление, если ответ не 2xx. Повтор не задваивает переписку: ключ сообщения —
  `tg:<чат>:<номер сообщения>`. Ненужные уведомления (кнопки, платежи, группы) подключение принимает ответом 200
  «пропущено» — иначе Telegram присылал бы их снова.
- Несколько компаний: `src/app/api/telegram/[company]/route.ts` — по номеру из адреса взять ключ и секрет своей
  компании и создать подключение на каждый запрос. Секрет проверяет само подключение.
- Новому клиенту — заявка, сделка, запись: хук `onContact` в `ingest(…, { hooks })` (как у других каналов).

## 5. Как сообщения попадают в переписку

- **Клиент — чат с ботом**: `ContactHint` = `{ source: "telegram", externalId: "<номер чата>", channel: "telegram",
  name: "Имя Фамилия", username: "ник" }`.
- **Телефона Telegram боту не даёт.** Если клиент сам поделится номером (кнопка бота «Поделиться номером» —
  `request_contact`), номер подлинный: Telegram подставляет его сам, чужой так не назвать. Такой номер идёт в
  `ContactHint` с `phoneTrusted: true` — переписка встаёт к клиенту, уже известному по этому номеру (например,
  оставлявшему заявку на сайте). В ленте — строка «Клиент поделился своим номером: +996 555 00-00-01». Чужой контакт
  и пересланный — только текстом «Контакт: …», телефон клиенту не ставится.
- **Время** — от Telegram, с точностью до секунды.
- **Файлы** — ссылками `tg-file:<file_id>`; `download()` берёт путь у Telegram (`getFile`) и скачивает файл по адресу
  с ключом бота. Лимит — 10 МБ (`maxFileBytes`; облачный Bot API отдаёт ботам файлы до 20 МБ). Тип — по содержимому
  файла (`sniffFile`), простой текст (txt, csv) — по расширению. Архивы, программы, старые форматы Office набор не
  сохраняет — и такой файл не пропадает молча: в тексте сообщения строка «Файл «Сканы.zip»: такой вид файлов в CRM
  не сохраняется»; слишком большой — «Видео (25,3 МБ): в CRM сохраняются файлы до 10,0 МБ».
- **Подпись к фото** — текстом сообщения, фото — следом (так раскладывает `ingest`). У документа в ленте — его имя.
- **Стикер** — «Стикер 😀» (картинку не качаем). **Геопозиция** — «Геопозиция: 42.874621, 74.569762 —
  https://maps.google.com/?q=42.874621,74.569762», место — с названием и адресом. Кубик и опрос — текстом. История,
  игра, счёт на оплату — «История Telegram — в CRM не показывается».
- **«Старт».** `/start` — строка «Нажата кнопка «Старт»». Ссылка `https://t.me/<ник бота>?start=<метка>` (на сайте,
  в письме, в рекламе) даёт «Нажата кнопка «Старт» (метка ссылки: <метка>)» — по метке видно, откуда пришёл клиент.
  Метка — до 64 знаков: латинские буквы, цифры, `_` и `-`.
- **Ответ с цитатой** — у сообщения `replyTo`: ключ цитируемого и начало его текста. Ответ менеджера из CRM получает
  ключ того же вида (см. раздел 6) — если проект сохранит его у сообщения, цитата клиента на ответ менеджера найдёт его.
- **Правка.** Клиент изменил сообщение — служебная строка «Клиент изменил сообщение: «новый текст»», одна на каждую
  правку. Прежний текст в ленте не меняется: на него уже могли ответить. Трансляция геопозиции (она обновляется
  правками каждые несколько секунд) — пропускается.
- **Блокировка.** Клиент заблокировал бота — строка «Клиент заблокировал бота в Telegram — сообщения ему не дойдут,
  пока он не разблокирует бота»; разблокировал — «Клиент разблокировал бота в Telegram — сообщения снова доходят».
- **Свои слова.** Строки выше, где есть слово «клиент», проект может заменить: `createTelegramAdapter({ …, texts:
  { blocked: "Пациент заблокировал бота…", edited: "Пациент изменил сообщение: «{text}»" } })` (`TELEGRAM_TEXTS` —
  все строки).
- **Группы** по умолчанию пропускаются. `privateOnly: false` — группа становится одним клиентом (название группы),
  у каждого сообщения — имя участника. Каналы не принимаются никогда.

## 6. Ответ из CRM

```ts
"use server";
import { readComposerForm } from "@muras/chat-kit";
import { createTelegramAdapter } from "@muras/chat-kit/telegram";

export async function sendMessage(clientId: number, form: FormData) {
  const d = readComposerForm(form);
  const telegram = createTelegramAdapter({ token: env("TELEGRAM_BOT_TOKEN"), secretToken: env("TELEGRAM_WEBHOOK_SECRET") });
  // права, запись в базу с delivery = 'pending', затем:
  const r = await telegram.send({ externalId: chatId /* ContactHint.externalId клиента */ }, {
    text: d.text,
    author: { type: "operator_crm", name: user.name, id: String(user.id) },
    replyTo: quote ? { externalId: quote.externalId } : null, // ответ с цитатой
    file: d.file ? { name: d.file.name, mime: d.file.type, data: new Uint8Array(await d.file.arrayBuffer()) } : undefined,
  });
  // r.ok — delivery = 'sent' и externalId = r.externalId («tg:<чат>:<номер>»); иначе delivery = 'failed', причина r.error
}
```

- **Текст.** Ответ бота (`author.type: "bot"`) написан разметкой Markdown — уходит с разметкой Telegram (**жирный**,
  *курсив*, ссылки). Текст менеджера уходит как набран: знаки `< > &` так и остаются знаками. Если Telegram не понял
  разметку — тот же текст уходит без неё.
- **Длинный текст** (больше 4096 знаков) — несколькими сообщениями по абзацам и предложениям; цитата — у первого,
  ключ — первого. Если не ушла одна из следующих частей — ошибка «Ушла только часть сообщения (1 из 2): …» без
  повтора: повтор задвоил бы уже ушедшие части.
- **Файл** — методом по типу: фото (jpeg, png, webp до 10 МБ) — фото; голосовое ogg/opus — голосовым; mp3, m4a —
  аудио; mp4 — видео; остальное (PDF, Word, Excel, большое фото) — документом. Подпись — до 1024 знаков; длиннее —
  файл без подписи, текст следом. Текст, равный имени файла, подписью не повторяется.
- **Голосовое из браузера.** Голосовым сообщением подключение отправляет только ogg/opus (так записывает Firefox);
  запись Chrome (webm) уходит документом, запись Safari (m4a) — аудиофайлом. Клиенту, который запретил присылать ему
  голосовые (настройка Telegram Premium), голосовое уходит документом.
- **Данные или ссылка.** Лучше передавать файл данными (`file.data`) — загрузка до 50 МБ, любой тип. По ссылке
  (`file.url`, например `signFileLink`) Telegram забирает файл сам, но только фото до 5 МБ, остальное до 20 МБ,
  а документы — только PDF, GIF и ZIP. Поэтому Word, Excel и файл, который Telegram не смог забрать, подключение
  скачивает по ссылке само (только https/http, не внутренние адреса, до 50 МБ) и загружает. Фото, которое Telegram
  не принял как фото (например, слишком вытянутый снимок экрана), уходит документом. `file.path` не используется.
- **Повтор.** У Telegram нет ключа повтора: повторная отправка дойдёт клиенту второй раз. Повторять — только ошибки
  с `retryable: true`; при `429` подключение говорит, через сколько секунд можно (`retryAfterSec`). После обрыва
  связи сообщение могло и уйти — лучше показать ошибку менеджеру, чем повторять самим.

Ошибки (`r.error`) — коротко по-русски:

| Когда | Текст | Повторять |
|---|---|---|
| клиент заблокировал бота | Клиент заблокировал бота — сообщение не дошло | нет |
| клиент удалил аккаунт | Аккаунт клиента в Telegram удалён | нет |
| клиент не нажимал «Старт» | Клиент ещё не писал боту — первым бот написать не может | нет |
| чат не найден | Чат не найден: клиент не писал этому боту или номер чата неверный | нет |
| слишком длинно | Сообщение слишком длинное для Telegram | нет |
| слишком часто (429) | Telegram просит подождать 7 с: слишком много сообщений подряд | да, через `retryAfterSec` |
| сбой у Telegram (5xx) | Telegram временно не отвечает (ошибка 502) — попробуйте позже | да |
| нет связи | Нет связи с Telegram / Telegram не ответил за 15 с | да |
| неверный ключ бота | Ключ бота Telegram не подходит — проверьте токен от @BotFather | нет |

## 7. Чего бот не умеет

`TELEGRAM_CAPS = { text: true, files: true, pause: false, mute: false, start: false, statuses: false }`:

- **Написать первым** (`start: false`). Telegram разрешает боту писать только тем, кто сам нажал «Старт» или написал
  ему; по номеру телефона бот клиента не найдёт. Пригласить клиента — ссылкой `https://t.me/<ник бота>?start=<метка>`
  (на сайте, в письме, в SMS).
- **Статусы** (`statuses: false`). Telegram не сообщает боту ни о доставке, ни о прочтении — у отправленного только
  «отправлено».
- **Пауза бота и «не отвечать»** (`pause`, `mute: false`). Бот здесь только доставляет сообщения — сам он клиенту
  ничего не отвечает. Если проект подключит к нему свой ИИ, паузу ведёт проект.
- **Приложения у бота нет**: переписка с клиентами ведётся только из CRM — сообщений «с телефона» у этого канала нет.
- Время — с точностью до секунды: сообщения одной секунды встают по порядку записи.
- Файлы клиента больше 20 МБ облачный Bot API боту не отдаёт. Свой сервер Bot API (`apiBase`) в режиме `--local`
  отдаёт файлы путём на диске — такие файлы подключение не скачивает.
- Telegram Business (бот отвечает от имени личного аккаунта), кнопки под сообщениями, платежи — не поддерживаются.

## 8. Для особых случаев

- `telegram.call(method, params)` — любой метод Bot API с ключом этого бота: например, `sendChatAction`
  («печатает…») или `setMyCommands` (меню команд бота).
- **Опрос вместо вебхука** (например, на компьютере разработчика без https-адреса): сначала `telegramDeleteWebhook`
  (вебхук и опрос одновременно не работают), потом в цикле `telegram.call("getUpdates", { offset, timeout: 10 })` и
  каждое уведомление — в `ingest` так же, как вебхук: `{ method: "POST", headers: { "x-telegram-bot-api-secret-token":
  секрет }, body: JSON.stringify(update) }`; `offset` — номер последнего уведомления + 1.
- `telegramUpdateEvents(update, { privateOnly, maxFileBytes, texts })` — тот же разбор уведомления без сети и без
  проверки секрета (для своих проверок).

## Проверка после подключения

- Написать боту `/start` — в CRM новый клиент с именем из Telegram и строкой «Нажата кнопка «Старт»»; клиент в
  «Ждут ответа».
- Прислать фото с подписью, голосовое и PDF — в ленте подпись текстом и файлы; голосовое играет.
- Ответить из CRM — клиент получил; ответ с цитатой — в Telegram видна цитата; длинный текст — пришёл частями.
- Заблокировать бота в Telegram — в ленте строка о блокировке; ответ из CRM — «Клиент заблокировал бота».
- `telegramWebhookInfo` — `pending: 0`, `lastError: null`.
