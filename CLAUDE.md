# chat-kit — нейтральная основа переписки: контекст для Claude Code

**chat-kit — собственная нейтральная основа переписки с клиентами** для любых проектов пользователя. В каждом проекте
ИИ берёт её за основу и докручивает под отрасль: у клиники — пациенты и запись на приём, у агентства — кандидаты
и вакансии, у магазина — заказы. Поэтому основа должна быть максимально полной и гибкой, а **названий конкретных
проектов в наборе нет** (решение пользователя 27.09.2026). Подход — **одна основа + докрутка в проекте**: набор —
пакет с номером версии; проект меняет слова, цвета, что включено, добавляет свои карточки и кнопки, не правя основу;
улучшения основы получают все проекты сменой версии. План работ и выбор пользователя — `docs/ROADMAP.md`.

Ваша ИИ-студия (проект aibots) — один из каналов набора (бот). Её план — артефакт «ИИ-продажник вместо Nextbot»
(https://claude.ai/artifact/9ceNCMMv2g9Lbj14oBX3Yc, файл `plan.md`; для подключения — разделы 10.4, 10.5, 10.8, 4.4).

Общайся с пользователем **на русском**, просто, без жаргона: термин — с пояснением одной фразой.
Пользователь не программист. Результат показывай экраном (демо-страница, снимки), а не кодом.
Для всего, что видно глазами, сначала 2–3 варианта — он выбирает (часто смесь «А + В»). Мелочи — сразу.
Он работает с двух компьютеров: заметки Claude между ними не переезжают — всё важное пишем сюда и в `docs/`.

## Устройство (подробно — `docs/ARCHITECTURE.md`)

- `src/core` — ядро без зависимостей: модель, «ждут ответа» (`waitSince` + `waitSinceSql`), порядок, телефоны, файлы,
  разметка, время, ссылки, форма поля ввода.
- `src/server` — «розетка» `ChannelAdapter`, «переходник» `ChatStore`, приём `ingest`, скачивание, подписи ссылок,
  переходник «в памяти» для тестов.
- `src/channels/<канал>` — подключения каналов (у каждого своя папка, тесты — `tests/channels/<канал>`).
- `src/ui` — окно (React 19), стили `src/ui/styles.css`. Серверные части (`ChatThread`, `DialogList`, `DialogHeader`,
  `ChatWindow`, `Attachment`) — без `"use client"`: функции в них передаются только как render-функции или
  действия-формы (server actions).
- `demo/` — демо-страница на Vite (выдуманная компания и клиенты), `scripts/demo-assets.mjs` делает голосовые и
  документы, `tests/` — vitest (ядро, каналы, окно в jsdom, серверная отрисовка, проверка архива выпуска).

## Как запускать

- Демо: через превью `chat-kit-demo` (`.claude/launch.json`) или `npm run demo` → http://127.0.0.1:30030;
  переключатели — вверху страницы; в адресе — `?dialog=…`, `show=…` (фильтр списка), `q=…` (поиск).
- Проверки: `npm run check` (типы + тесты + сборка). npm в bash — `"C:\Program Files\nodejs\npm.cmd"`, либо
  `node node_modules/vitest/vitest.mjs run`, `node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json`.
- Сохранение работы: коммит в рабочей ветке и `git push origin HEAD:main`.
- Выпуск: поднять `version` в package.json + раздел в `CHANGELOG.md` → `npm run release -- --dry-run` → по «да»
  пользователя `npm run release` (метка vX.Y.Z и выпуск с архивом на GitHub). Ссылки в README и CONNECT.md — на новую
  версию.

## Подводные камни (уже встречались)

- Импорты в `src` — с расширением `.js` (иначе собранный код не откроет Node).
- `exactOptionalPropertyTypes`: необязательные поля пишем `?: T | null | undefined`.
- У набора нет зависимостей (только React для окна) — каналы пишем на `fetch` и `node:crypto`, `fetch` передаётся
  в подключение (в тестах — поддельный, внешняя сеть в тестах запрещена).
- Vite не отдаёт файлы, появившиеся в `public/` после запуска: файлы демо делаются до старта сервера (в `vite.config.ts`).
- В jsdom нет `scrollTo` — вызывать `el.scrollTo?.()`.
- Картинки докачиваются после открытия ленты — прокрутку вниз держит `ResizeObserver` в `ChatScroller`.
- Проверка архива (`tests/package.test.ts`) ищет в `dist` строки, похожие на секреты, и «настоящие» телефоны — примеры
  номеров в комментариях только из нулей: `+996 555 00-00-01`.
- Светлый (например, лаймовый) акцент плохо читается текстом: для ссылок, галочек и значков — свои переменные
  (`--ck-link`, `--ck-tick`, `--ck-accent-ink`), цвета значков каналов — постоянные.

## ЖЕЛЕЗНЫЕ ПРАВИЛА

- **Проекты пользователя — только чтение.** Проекты, которые берут набор, в этом чате не менять и не запускать: их
  докручивают их собственные чаты. Параллельно идут другие чаты пользователя.
- **Нейтральность.** В коде, описаниях и демо набора — никаких названий проектов пользователя и их подробностей.
  Особенности отрасли — через паспорт проекта, свои карточки и кнопки, а не правкой основы.
- **GitHub.** Репозиторий `kumerovich312-dotcom/chat-kit` **открытый** (решение пользователя 27.09.2026): его видят все.
  Поэтому в нём нет секретов и нет подробностей устройства проектов пользователя (серверы, выкладка, служебные ключи и
  адреса). Новые выпуски (`npm run release`) — по «да» пользователя.
- **Секреты.** Не просить и не хранить: ни ключей каналов и ИИ, ни адресов вебхуков, ни паролей. В тестах и демо —
  только обезличенные примеры: без настоящих телефонов, имён и ключей. Тестовые «ключи» — только вида
  `test-secret-not-real-…` (так требует проверка секретов студии); не писать имён вида `…sk-` + 20 знаков
  (например `task-…`, `desk-…`) — их ловит поиск секретов студии.
- **Код набора собирается в любом проекте:** строгие флаги TypeScript (`strict`, `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes`); без Tailwind (свои стили, классы `ck-…`); без `blob:`-адресов для картинок и голосовых
  (строгие правила безопасности страницы у студии) — только прямые ссылки сайта; текст бота — не как HTML.
- **Порты.** Демо-страница — 30030, пример проекта — 30031. Порты ниже 15000 на этом компьютере Windows резервирует
  блоками — не использовать. Заняты другими проектами: 30003, 30004, 30014, 30020, 30021, 30097, 30099, 35432.
- **Node и npm.** В bash `node` доступен (v24), npm — через `"C:\Program Files\nodejs\npm.cmd"`.
- **Запись файлов.** Код с обратной косой чертой (регулярки) — только через Edit/Write: heredoc и `node -e` теряют `\`.
- **Обходы канала — только в его подключении.** Разбор «Полного диалога» Nextbot, угадывание времени и автора в ядро
  не идут.
